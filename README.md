# TeX Navigator

おいとまハッカソン2026向けの日本語LaTeXリファレンス。**探す → 試す → 直す**を、ブラウザだけで使える静的SPAとして実装しています。

React / TypeScript / Vite / HashRouter / KaTeX / 型付きJSON。APIサーバー・ログイン・TeX Live・OpenCodeは基本機能に不要です。開発中の通常画面から学内LLMへ接続し、実APIで回答とLaTeXコードを取得できることを確認しました。仕様は [DESIGN.md](./DESIGN.md)、実装依頼は [CODEX_PROMPT.md](./CODEX_PROMPT.md) を参照してください。

**発表・配布の方針**：一般観覧者へはLLM接続なしの静的アプリを配布し、実装済みの全基本機能を利用できる形にします。LLMは開発中の通常画面で使い、発表動画でも紹介します。配布版にキー入力・外部公開する中継サーバーを追加しません。実接続は確認済み、動画収録は未実施です。[配布版と発表動画の範囲](./docs/PRESENTATION_DEMO.md)に記録しました。

**開発中のLLM接続**：`.env.example` を `.env.local` へコピーし、`OITOMA_API_KEY`・`OITOMA_MODEL` を設定して `npm run dev` を実行します。「まとめて調べる」で質問とTeX・ログを添付／貼り付けて「送信」します。接続は入口で自動確認し、利用できない場合は入力画面を出しません。厳密な学内Wi-Fi限定ではなく、APIの利用可否による制限です。キーはサーバー側のみ。`npm run build` の配布物にはLLM接続のUI・API処理を含めません。[起動・情報の扱い・制限](./docs/LLM_CONNECTION.md)を参照してください。

デザインは2010年代の簡素なWebサイトを意識し、白背景、落ち着いた青いリンク、控えめなボタン、細い区切り線の一覧にしています。書体・余白・見出しを揃え、PCの検索結果は説明とコード例を横に並べ、スマホでは縦に並べます。選択中のタグは結果の上に表示し、検索語を保ったまま個別に解除できます。日本語の読みやすさと操作性を保ち、大きな装飾・影・グラデーションは使っていません。

共通ナビの「探す・試す・直す・まとめて調べる」から操作を選び、テーマ別資料・日本語文書・学習コースは「資料・学習」から開けます。見出しの重複や常時表示の接続案内を省き、質問画面は入力・添付・送信を中心にしました。貼り付け・文字コード・関連資料は必要時に展開します。検索は57項目を横断し、目的・症状の言い換えにも対応。カテゴリ・症状は折りたたみ、結果は先頭8件から追加表示します。検索結果から戻ると検索語・種類・タグを保ちます。[横断検索の仕様](./docs/SEARCH_AND_AI.md) を参照してください。

ギリシャ文字・記号は86種類を8分類にまとめ、同じページ内で必要な分類を開けます。日本語名・別名・コマンド・形から絞り込み、個別コピーもできます。長い診断結果、テーマの補足、出典一覧、Overleaf向け設定も段階的に表示します。[必要な情報を読む工夫](./docs/USABILITY.md)に詳細を記載しました。

基本ページの初期JS・CSSは **gzip 108,417 bytes（105.9KiB）**。画面・数式用資産・テーマ別資料・将来Gatewayを遅延読み込みし、不要なUI・CSSも削除しました。本番CSP、応答の容量制限、依存監査とビルドのサイズ上限は [セキュリティと読み込み量](./docs/SECURITY_AND_PERFORMANCE.md) に記録しています。

UI整理後の確認（2026-10-12）：lint・build成功、単体/UI549件、配布版E2E66件、LLM画面のモックE2E6件成功。PC・モバイル、320px幅・200%文字、コピー・資料への移動・入力の非保存・アクセス制限を検証しました。

## 大学生・授業での使いやすさ

テーマ別資料は、大学の **Linux／Emacs** と自前の **Windows／TeX Live** を主な利用環境として案内します。大学PCのTeXエンジン・文書クラス・Emacsのモードは未確認のため、設定やショートカットを決め打ちしません。公式・保守者文書と制作元のチュートリアルを区別し、16項目に出典を付けました。資料の構成と編集手順は [テーマ別資料の試作](./docs/REFERENCE_CONTENT.md) を参照してください。[テーマ一覧のローカルデモ](http://127.0.0.1:4173/oitoma-dev/#/reference)から読めます。

ヘッダーの「利用環境」で **Linux / Emacs・Windows / TeX Live・その他のエディタ** を選ぶと、「日本語文書」「直す」「まとめて調べる」で操作案内を開けます。選択はページ間で保持し、再読み込みで未選択に戻ります。自動検出・保存・外部送信は行いません。エンジン・文書クラス・文字コードや入力・診断結果は切り替えず、授業指定の設定を優先します。

日本語スターターは **jlreq** のLuaLaTeX / upLaTeX用文書を固定の選択肢から生成します。授業指定のテンプレート・エンジン・引用規則を優先してください。文書全体はKaTeXプレビュー対象外で、TeXコンパイル検証も実施していません。生成後のPDF作成は授業の環境やOverleaf等で行います。エンジンを選ぶと、保存名と対応するPDF・ログ名、環境別の手順を表示します。LinuxではEmacs標準TeXモード／AUCTeX／不明を手動選択できます。ターミナル用の固定コマンドと、Overleaf設定は必要時に展開・コピーします。コマンドはアプリから実行しません。詳細は [学生向けの環境・検索・ログ案内](./docs/STUDENT_SUPPORT.md) を参照してください。

学習コースは目的別の4ステップと、理由を確認できる一問クイズです。チェックは本人の確認メモで、習熟度の判定や成績ではありません。進捗・クイズ回答はメモリ上だけで扱い、再読み込みで消えます。共有リンクにはコースIDだけを含め、進捗や回答を送信しません。学習シートはブラウザの印刷機能を使い、アプリによるTeX/PDF生成は行いません。

レシピの「生成コードを診断する」は、レシピIDと検証済みの選択値を履歴に渡し、診断画面で固定コードを再生成します。診断欄に貼り付け・編集したLaTeXソースはURL・履歴・Storageに含めません。

文字の拡大はブラウザのズーム機能で行えます。キーボード操作、本文へのスキップ、フォーカス表示、コントラスト、320px幅・200%文字表示も検証対象です。axe-coreのWCAG関連ルールによる自動検査を追加しました。自動検査だけでWCAGへの完全適合を保証するものではありません。

企業・大学の評価者に説明できる実装と検証根拠、授業でのデモ例、今後の実証課題は [教育利用・評価向け資料](./docs/EDUCATION.md) に整理しています。学習効果・採用実績・審査での加点を実証したという主張はしていません。

## GitHub Pagesへの公開（所有者が手動で行う操作）

**現在はデプロイ定義のみを用意しています。GitHubへのpush、Pages設定変更、公開は実施していません。**

1. 変更をレビューし、公開してよい内容か確認したうえで、所有者がcommit/pushします。
2. GitHubリポジトリの **Settings → Pages → Build and deployment → Source → GitHub Actions** を選びます。
3. `main`へのpush、または **Actions → Verify and deploy GitHub Pages → Run workflow** で実行します。設定前に失敗した場合は、設定後に再実行します。
4. `npm ci → 依存監査 → lint → test → build（データ・CSP・サイズ検証を含む） → Chromium E2E → dist配信` を通過すると公開されます。PRは検証だけを行い、配信しません。
5. Pagesに表示されたURLを開きます。このリポジトリの想定URLは `https://TKM0627.github.io/oitoma-dev/#/search` です。**公開済みURLを示すものではありません。**

ワークフローはビルド側に `contents: read`、配信側に `pages: write` と `id-token: write` を限定して付与します。公式ActionsはコミットSHAで固定しています。実際のGitHub Actions実行・公開環境は未検証です。

### base・独自ドメインの変更

- リポジトリサイト：`/<repo>/`。`vite.config.ts` の既定値は `/oitoma-dev/`、CIはリポジトリ名から設定します。
- ユーザーサイト `https://<user>.github.io/` または独自ドメイン：`/` に変更します。
- ローカル変更は `.env.example` を `.env.local` にコピーして `VITE_BASE_PATH=/` などを指定します。
- CIで変更する場合は `.github/workflows/deploy.yml` 内の **buildとE2E両方** の `VITE_BASE_PATH` を揃えます。
- 再ビルドが必要です。HashRouterのため、`/<repo>/#/recipes/matrix` の再読込にSPA用404回避ページは不要です。

### 一時公開・公開停止

一時公開も一般公開です。所有者が公開の開始を決めた後に上の手順を実行し、デモ終了後は **Settings → Pages → Unpublish site** で配信を停止します。再度のpushで再公開しないよう、Actionsの当該ワークフローも無効にするか、デプロイのトリガーを削除してください。再公開する場合はワークフローを有効化して手動実行します。

GitHub Pages本体の公開を学内Wi-Fi/VPNに限定する仕組みはありません。学内限定公開が必要な場合は、大学の承認済みホスティングへ設計変更が必要です。サイトを停止しても公開リポジトリのソースは閲覧可能です。

## プライバシーと安全設定

- 検索・レシピ生成・診断はブラウザ内で完結します。収録JSON・KaTeX・フォントはビルドに含め、CDNから取得しません。
- 専用セクションの質問・ファイル名・ソース・ログ・結果もReact stateのみです。`.tex`は64KiB・10,000文字、`.log`は256KiB・100,000文字まで。失敗時に入力を保持し、遅い読み込みをクリア・編集・離脱後には反映しません。
- 診断コードはReact stateのみ。サーバー送信、LLM送信、localStorageへの自動保存、ログ送信、解析SDK、アップロードはありません。診断画面を離れると入力を破棄します。
- 検索語は専用のReactメモリで保持し、URL・history state・Storage・APIへ保存・送信しません。検索結果へ戻るときは維持し、クリア・再読み込み・文書離脱で破棄します。URLへ残すのは登録済みタグ・結果の種類・全項目表示・コースIDです。旧形式の `q` 付きリンクは100文字以内の検索語をメモリへ取り込み、現在のURLを置き換えます。既に他の場所に保存された旧リンクや過去の履歴は削除できません。
- 自動修正は行いません。「例を読み込む」「入力をクリア」は明示操作で入力を置き換えます。
- 入力・ライブ解説をHTMLとして挿入しません。KaTeXに渡すのは固定レシピの出力だけです。`trust: false`、`maxExpand: 200`、`maxSize: 10`、描画例外処理を設定します。
- 参考URLは管理対象の開発元・保守者文書と制作元のチュートリアルのHTTPSのみ。正確なホストとパスを検証し、認証情報・クエリ・独自ポートを拒否します。新規タブは `noopener noreferrer` と `referrerPolicy="no-referrer"` を指定します。
- Viteの `VITE_` 変数は公開されます。3種類の承認済み設定以外はビルド・開発起動を拒否し、値をエラーへ出力しません。AI無効時もGateway URLの認証情報・クエリ・曖昧なパスを拒否します。ソースマップ・秘密ファイル・秘密鍵が成果物へ混ざった場合もビルドを失敗させます。文章の意味から機密情報を完全検出する機能ではありません。
- 本番HTMLにCSPを出力し、外部・インラインスクリプトとevalを許可しません。未設定時のfetch等の通信はCSPでも禁止します。開発用HMRでは同じCSPを適用しないため、本番の確認はbuild後のE2Eで行います。
- 将来Gatewayの応答はJSONのみ、本文32KiB・取得3秒以内に制限します。宣言された容量に加え、実際のストリームの合計を数えます。
- `npm run build` は初期JS・CSSを生サイズ380,000 bytes / gzip 110,000 bytes以内に制限し、結果を `dist/build-report.json` に出力します。CIは依存監査のhigh/critical検出時に停止します。

## 学内AI：未設定のまま使う

大学側に確認する情報は [学内LLM連携に必要な情報](./docs/LLM_INTEGRATION_CHECKLIST.md) に一覧化しました。2026-10-12の承認済み依存監査（npm audit）は、報告された脆弱性0件で成功しました。

既定値は次のとおりです。MVPで変更する必要はありません。Pages workflowでもライブAIを明示的にfalseに固定しています。

```dotenv
VITE_ENABLE_LIVE_AI=false
VITE_UNIVERSITY_GATEWAY_BASE_URL=
```

`false`・空URL・無効なURLでは `not-configured` になり、fetchも実行しません。デモ用の架空の「接続成功」は表示しません。基本機能と静的解説は利用可能です。

### 将来連携のインターフェース

`AiProvider.getExplanation({ explanationId, topicId, variant: 'brief' })` は登録済みIDだけを受け取り、解説文と関連IDを返します。

- `StaticProvider`：`reviewed === true` の説明のみ返します。
- `NetworkChecker`：注入可能なfetchで固定HTTPS Gatewayの `GET /v1/capabilities` を確認します。
- `UniversityGatewayProvider`：許可されたID/トピックの組み合わせだけを `POST /v1/explanations` に送ります。原文・任意プロンプト・任意URLを送る引数はありません。失敗・不正応答は静的解説へ戻ります。
- `AiSearchProvider` / `UniversitySearchProvider`：ローカル検索の候補から登録済みの種類・IDを選ぶ契約案。検索語・入力コードは送らず、未設定・非対応・不正応答時はローカル結果に戻ります。現在の画面からは呼び出しません。
- 自由なURL設定UI、ブラウザからのOpenCode生API呼び出し、自前Gatewayはありません。

横断検索の範囲、検索用データの更新、`POST /v1/search-navigation` の契約案は [横断検索と学内LLMの接続準備](./docs/SEARCH_AND_AI.md) を参照してください。自由な自然文をLLMに送る検索やチャットは実装していません。

**以下の契約は提案段階であり、大学側で未確定です。** 大学が承認・運営するGateway、HTTPS/TLS、学内Wi-Fi/VPNからの経路、許可OriginのCORS、認証・認可、IDホワイトリスト、レート制限、ブラウザのLocal Network Access対応が必要です。現在は `credentials: omit` を使い、認証情報を埋め込みません。SSO・Cookieなどの実際の認証方式は大学の仕様確定後に設計・検証してください。

```http
GET {承認済みGateway}/v1/capabilities
```

```json
{"service":"latex-navigator-ai","version":"1","ai":{"explanations":true}}
```

`200`とこの構造を両方確認します。補足説明には `ai.explanations === true` が必要です。横断検索の契約案では任意の `ai.searchNavigation: true` を追加し、この宣言がないGatewayへ検索要求を送りません。どちらか一方が提供されれば接続状態は `available` ですが、各操作は対応する機能を別に確認します。

```http
POST {承認済みGateway}/v1/explanations
Content-Type: application/json
```

```json
{"explanationId":"outside-math-subscript","topicId":"math-subscript","variant":"brief"}
```

```json
{"explanationId":"outside-math-subscript","text":"補足説明","relatedTopicIds":["math-subscript"],"referenceIds":["overleaf-scripts"]}
```

| 状態 | 意味 |
| --- | --- |
| `not-configured` | 連携なし。基本機能を使える |
| `checking` | 確認中。AI操作は無効 |
| `available` | 契約に合うサービス応答を確認。SSIDや本人認証の証明ではない |
| `authentication-required` | JSから読めた401/403。大学の認証手順が必要 |
| `unavailable` | 非200のサービス応答、または解説・検索のどちらも提供されていない |
| `unknown` | ネットワーク・CORS相当・期限・不正JSON等。原因を断定できない |

初回、タブ復帰、手動の「再確認」でチェックし、頻繁なポーリングは行いません。3秒で打ち切り、成功は60秒で失効します。AI利用直前に期限を確認して再検証します。応答本文の取得も期限に含めます。LLM操作は利用者が明示したときのみで、例のページを開くだけでは生成要求を送りません。

同梱JSONはビルド・開発サーバー起動時にスキーマ・重複ID・関連参照・生成関数・既定値・HTTPS URL・コードの制御文字を検証し、同じ検証をテストで実行します。不正なデータは本番ビルドを失敗させます。基本ページでは検証ライブラリの取得・検証を繰り返しません。外部応答や画面間の引き継ぎ値は実行時にも検証します。学習コースの参照先、クイズの選択肢と正答、日本語案内の出典も検証します。追加時はIDを揃えてください。生成関数はコード内の固定レジストリに追加し、`eval`や動的テンプレート評価を使わないでください。

テーマや関連トピックのタグを編集したら `npm run update:search-index` を実行し、`reference_search_index.json` の差分を確認してください。元データと一致しない検索用データは起動・ビルド時に拒否します。

共通の37資料と、環境・追加ログ案内用の6資料（計43資料）に種類・確認日・発行元・参照範囲・利用方法を記録し、画面から確認できます。Overleafの解説はサービス提供元の解説、Learn LaTeXは制作元のチュートリアルとして表示し、LaTeX本体の公式仕様と同一視しません。静的解説は解説固有、テーマ別資料は項目ごとの出典IDを持ちます。JSONの未知の項目や出典情報の欠落は拒否します。資料の全文・画像・配布テンプレート全体は収録せず、短い構文例と日本語の説明を作成しています。詳しくは [情報利用と確認状況](./docs/INFORMATION_POLICY.md) を参照してください。

説明はAIを利用して作成し、開発時に登録資料と照合しています。**教員などによる人手校閲は未実施**です。`reviewed`は資料との照合を終えた説明を表示する管理フラグであり、人手校閲を意味しません。`verificationMethod`と`humanReview`を別に記録し、画面にも未実施を表示します。テーマ別資料は試作状態と、TeXコンパイル未実施も記録します。CODEX_PROMPT.mdが想定する人手検証は未完了です。今後編集する解説は資料と照合するまで `reviewed: false` にしてください。

実行時の依存ライブラリのバージョンとライセンス通知は [THIRD_PARTY_NOTICES.txt](./public/THIRD_PARTY_NOTICES.txt) に収録し、本番成果物にも同梱します。

## 対応範囲と未実装

- 完全なTeX解析・コンパイル・PDF生成・サーバーへのファイルアップロード・LLMチャットは対象外です。
- 指摘ゼロでも文書の正しさを保証しません。断片の前後が欠ける場合、閉じ忘れはwarning/hintです。
- コメント、エスケープ、`$`・`$$`・`\(\)`・`\[\]`、主な数式環境、制限付き `\verb`・`verbatim` に対応します。参照キー・ファイル名・URLの引数はリテラルとして読み飛ばします。
- マクロ定義・catcode変更・外部ファイル読み込み・動的環境指定が現れた位置以降は、誤判定を避けるため診断を省略します。未知の独自マクロ、条件分岐、パッケージ固有構文は解釈しません。
- minted・lstlisting等のリテラル環境は読み飛ばしてヒントを出します。未完のverb/verbatimもヒントです。
- 行/列は1始まり（列はJavaScript文字列のUTF-16単位）。指摘表示は先頭100件までとし、超過時は分割のヒントを付けます。
- KaTeXの対応範囲とTeXの有効性は別です。図・表・文書構造の選択式レシピは未収録で、数式10種類のみです。
- コピーはClipboard APIを使います。HTTPSまたはlocalhostとブラウザの許可が必要です。失敗時はコードを選択して手動コピーする案内を表示します。
- 完全オフラインの初回起動・PWAキャッシュは未実装です。静的ファイルの初回読み込みには配信サイトへの通信が必要です。
- 実API・大学認証・GitHub上の実デプロイは未検証です。E2EはChromiumのPCとモバイルエミュレーションであり、iOS/Safari・実機は未検証です。

## デモ例

「まとめて調べる」で「分数を大きくしたい」を入力し、`.tex`と任意の`.log`を選んで確認。`dfrac`の例をコピーし、指摘の行に移動して確認できます。関連例・出典・数式表示は必要時に開きます。

1. 「探す」で「分数」を検索 → 書き方・試せる例・テーマ別資料・エラー・学習を比較 → 「試せる例」で絞り込み → 直接レシピを試し、「検索結果に戻る」で条件を復元。
2. 「探す」で `Missing $ inserted` を入力 → 下付き文字 → 数式外の下付き記号 → 修正例を比較。
3. 下付き文字の「試す」で `ij` に変更 → `{ij}` と数式表示を確認 → コピー。
4. 行列レシピで丸括弧から角括弧・縦線に変更 → コード・プレビューを比較。
5. 「直す」で `x_1` を診断 → 1行2列の注意 → `$x_1$` に変更して再診断 → 簡易規則で未検出という表示を確認。
6. 学内AIが「未設定」のまま、上のすべての機能が動くことを確認。
7. 「日本語が出ない」で検索 → 日本語文書のガイド → スターターで実験レポートを選ぶ → `.tex` 保存。
8. 学習コースの数式を選ぶ → 確認チェック → 添字クイズで理由を読む → コースリンクをコピー／学習シートを印刷。
9. ブラウザで文字を拡大し、スマートフォン表示でも操作を確認。
10. 「テーマ別資料」で環境の準備を読む → 数式の短い例をコピー → 項目の出典と参照範囲を確認 → 行列のレシピを試す。ブラウザから資料を印刷。
