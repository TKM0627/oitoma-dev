# 教育利用・評価向けの実装根拠

TeX Navigatorは、大学生が書き方・エラー原因を自分で確認できる日本語の静的SPAです。DESIGN.mdのMVPを実装した後、学生の使いやすさと授業での案内を高める追加機能を実装しました。企業・大学の評価者には、以下の動作と検証をデモできます。審査の加点、学習効果、大学への導入実績を保証・実証した資料ではありません。

## 学生の課題と実装

| 課題 | 実装した対応 | 確認できる根拠 |
| --- | --- | --- |
| どの画面を使うか迷う | 3つの目的の入口、57項目の横断検索、種類と次の操作、検索条件を保って戻る導線 | PC/モバイルの検索・直接レシピ・戻る・再読込のブラウザ検証 |
| 質問と手元のファイルを一緒に確認したい | 専用セクションで固定例・簡易チェック・タイポ候補・ログ報告を表示。コピーと行への移動 | 実ファイル・文字コード・容量上限・入力保持・非送信・再読込のブラウザ検証 |
| コマンド名を知らない | 日本語の目的・症状・エラー文・タグから検索 | 検索の正規化/関連語テスト、検索→詳細のE2E |
| 日本語文書の設定でつまずく | jlreqによる一般・実験レポート、LuaLaTeX/upLaTeXの手順、UTF-8保存 | 固定生成器の4組合せの検証、実ブラウザでの保存と内容確認 |
| 何から学ぶか迷う | レポート・数式・実験の3コース、各4ステップ | JSONの参照整合性、コース切替と自己チェックのUIテスト |
| テーマごとに読み、授業の環境で使いたい | 6テーマ・16項目の資料、Linux／Emacs・Windows／TeX Liveの案内、短い例と項目別の出典 | 全テーマの直接リンク・コピー・出典付き印刷・関連レシピのブラウザ検証。大学固有の設定は未確認と明示 |
| 記号が多くて探しにくい | 86種類を分類別に展開し、名前・別名・形で検索してコピー | 遅延読み込み・非保存・開閉・印刷・幅320pxでの検証 |
| 長い補足や指摘を一度に読みきれない | 要点と先頭の指摘を表示し、残りや出典を同じページ内で展開 | 利用条件・診断の限界は表示を維持、折りたたみのキーボード検証 |
| コード例を見ても理由が分からない | 操作できるレシピ、理由付き確認クイズ | 全レシピ選択肢の生成/KaTeX検証、正誤の解説表示テスト |
| コピー後の移動が面倒 | 選択したレシピを診断欄で再生成 | 行列の選択→診断のE2E、編集ソースを履歴に残さない検証 |
| 小さい文字やスマートフォンで読みづらい | ブラウザの拡大に対応、折り返し、キーボード/フォーカス/スキップ操作 | PC/モバイル、幅320px・文字200%、axe-coreの自動検査 |

日本語設定は公開一次資料に基づく案内です。授業のテンプレートが最優先です。スターターの完全TeXコンパイルは未検証で、アプリはエンジンの実行・PDF生成を行いません。クイズは一般的な構文理解の確認で、提出物の採点や習熟度の認定には使いません。

## 企業・大学に説明できる点

| 観点 | デモ・レビューで示す事実 | 評価上の限界 |
| --- | --- | --- |
| 教育への適用 | 教員がコースURLを配布し、ブラウザで学習シートを印刷できる | LMS連携、学生管理、成績保存はない |
| 導入と運用 | GitHub Pagesに静的配信でき、基本機能にログイン/API/常時稼働サーバーが不要 | 大学の公開規程への適合・採用承認は別途必要。Pagesの実配信は未検証 |
| データの保護 | 入力ソース・進捗・クイズ回答を保存/送信せず、解析SDKを入れていない | 読み込み・外部資料への通信はある。検索語もURL・履歴へ保存しない。公開教材を学内限定にするには別の配信環境が必要 |
| 説明と検証のしやすさ | 資料の種類・確認日・参照範囲、解説・テーマの項目ごとの出典、固定コード生成、規則IDと行/列を明示 | AIを利用した説明は資料と照合したが、人手校閲は未実施。簡易診断は完全なTeX解析ではない |
| 品質管理 | TypeScript、ビルド時のデータ検証、単体/UI/E2E、本番CSP、依存監査、初期資産のサイズ上限 | 自動検査はWCAG完全適合や完全な安全性の証明ではない。Safari・実機・支援技術による確認は今後 |
| 将来の拡張 | 学内AIの型付き契約、解説と横断検索の機能別判定、ローカル結果へのフォールバック | 実APIは未確定・未接続。大学の許可、認証、CORS等が必要 |

導入の軽さ、データ保護、出典、検証可能な品質は、評価者に説明する材料になります。評価基準は審査主体ごとに異なるため、これらを加点の保証として提示しません。

情報の出典、利用範囲、入力の流れ、未実施の確認は [情報利用と確認状況](./INFORMATION_POLICY.md) に記録しています。登録資料との照合、動作テスト、教員の校閲、実際のTeXコンパイルを区別して説明します。

安全性と軽量化の実装、初期JS・CSSの約27.4%削減というサイズ計測、公開環境での制限は [セキュリティと読み込み量](./SECURITY_AND_PERFORMANCE.md) に記録しています。

## 授業・審査での短いデモ

1. 「分数」で書き方・試せる例・テーマ別資料・エラー・学習を一緒に検索し、種類で絞り込んでレシピへ進む。「検索結果に戻る」で条件を復元する。
2. 「日本語が出ない」からスターターを開き、エンジンと構成を選ぶ。授業指定優先とコンパイル対象外の説明を示す。
3. 数式の学習コースで、添字のレシピを試す。生成コードを診断へ渡す。
4. `x_1`と`$x_1$`の診断結果を比較し、入力を勝手に修正しないことを示す。
5. クイズで誤答を選び、理由を確認する。正解だけでなく構文の理由に戻れることを示す。
6. ブラウザで文字を拡大し、コースURLの共有・印刷表示を確認する。再読み込みで確認状況が消えることを示す。

## 今後、実証で確かめること

- 学生の同意と大学の規程に従った授業内試用で、検索から必要な例への到達率、課題完了までの時間、分かりにくい説明を確認する。
- 教員がスターターの書式・引用案内を授業指定と照合する。実環境のTeXコンパイル、指定フォント、提出形式を検証する。
- キーボードのみ、スクリーンリーダー、Safari、実機スマートフォンで使いやすさを確認する。
- 学習効果を主張する前に、構文理解の事前/事後評価や比較条件を設計する。現状の自己チェック件数を成果の指標にしない。

これらの実証は未実施です。アプリに利用追跡や個人情報収集を追加せず、将来実施する場合は収集目的・同意・保存期間等を別途設計します。
