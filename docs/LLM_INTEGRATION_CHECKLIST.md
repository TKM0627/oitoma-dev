# 学内LLM連携に必要な情報

作成日：2026-10-12。大学担当者へ確認するための一覧です。大学のAPI仕様・許可を示す文書ではありません。秘密の値や実際の学内接続先は記入せず、大学指定の安全な経路で共有してください。

## まず確認する5項目

1. この公開Webアプリから、学生向けに学内LLMを利用してよいか。担当部署・承認者・対象利用者。
2. API仕様書と、利用可能なモデルID。秘密情報を除いた要求・応答のサンプル。
3. 学生の認証・認可方式と、学内Wi-Fi／VPN／学外からの利用条件。
4. 質問・TeX・ログを送信できる範囲、および保存期間・学習利用・閲覧者。
5. 大学が管理するHTTPS Gatewayの有無、または設置の可否と管理担当。

APIキーそのものは、この確認段階では不要です。

開発中の通常画面で使う学内LLM接続は、追加依頼により通信処理を実装しました。配布ビルドでは無効にします。公開サービス向けの条件確認とは分け、APIキーはチャットへ送らず端末の `.env.local` に設定します。[接続手順](./LLM_CONNECTION.md)を参照してください。自作の短い質問による実APIでの回答取得は確認しました。大学による承認・保存期間・Wi-Fi限定の仕様の確認は未完了です。

2026-10-12に調査報告を受領しました。互換API・CORS・モデル上限などは、報告に基づく候補であり、今回の環境では一次資料未照合です。未確認を承認済みに変更せず、[報告の整理](./LLM_RESEARCH_REVIEW.md)に判断と次の確認事項を記録しました。

## OpenCodeを使う場合に追加で確認すること

- サーバーの版とAPI仕様、大学指定のProvider／モデル設定、実行場所・管理担当。
- GatewayとOpenCode間の認証。OpenCodeの生APIをブラウザへ直接公開しない構成。
- セッションの所有者確認・利用者間の分離・保持期間・削除・共有禁止の設定。
- ファイル閲覧・書き込み・シェル・Web取得・MCP・プラグイン等の権限。回答に不要な操作は拒否し、隔離した実行環境と通信先制限を用意する方針。
- 学内モデルだけを使う設定、外部モデルへの自動切替の有無、会話以外にモデルへ渡される作業フォルダ・設定・追加コンテキストの範囲。

## 現在のアプリとの違い

現在は未接続です。登録済みIDだけを送る解説と候補選択の契約、および接続判定の準備があります。質問・TeX・ログをモデルへ送る機能、学生の認証、大学側Gatewayは実装していません。

`VITE_ENABLE_LIVE_AI=true` に変えるだけでは、自由な質問への回答や安全な認証は完成しません。認証方式が決まると、現在のCookie非送信の処理も含めて適合を確認します。現行の3秒・32KiBは限定IDの契約向けで、自由な回答生成の待ち時間やストリーミングは別途設計します。Pagesの配信設定も現在はAI無効です。

設計の詳細：[検索用契約案](./SEARCH_AND_AI.md)、[質問・ファイルの範囲](./WORKSPACE.md)、[情報管理](./INFORMATION_POLICY.md)、[防御と検証](./SECURITY_AND_PERFORMANCE.md)。情報を揃えた後も、大学の承認を受けたテスト環境で確認してから実接続へ進みます。
