# 横断検索と学内LLMの接続準備

更新日：2026-10-12。検索はブラウザ内で動作します。学内LLMの実APIは未確定・未接続です。以下の検索用Gateway契約は提案であり、大学の仕様や承認を示すものではありません。

## 現在の検索

| 種類 | 件数 | 結果から進める操作 |
| --- | ---: | --- |
| 書き方 `topic` | 32 | 構文・条件を読む、関連レシピを試す |
| 試せる例 `recipe` | 10 | 選択肢を変え、コードと数式表示を確認する |
| テーマ別資料 `reference` | 6 | 要点・例・確認ポイントを読む |
| エラー `error` | 5 | 原因と修正前後の例を比べる |
| 日本語スターター `guide` | 1 | 文書全体の土台を用意する |
| 学習コース `course` | 3 | 手順とクイズで学ぶ |

合計57項目を共通の検索対象にしています。「分数」では構文、レシピ、数式テーマ、関連エラー、学習コースを比較できます。結果には種類と次の操作を示し、種類別の件数から絞り込めます。先頭8件と追加表示を使い、検索中はカテゴリ・症状の補助操作を畳みます。検索結果から直接開いた画面には、検索語・種類・タグを保持した「検索結果に戻る」を表示します。検索ボタンを押すと結果見出しへフォーカスを移します。

検索語はReactメモリ内だけに保持し、URL・history state・Storage・APIへ渡しません。旧リンクの `q` はメモリへ取り込んだ後、現在のURLから除きます。種類・表示・登録済みタグ以外のURL項目も除きます。再読み込みと明示クリアで検索語を破棄します。

入力は最大100文字、不可視制御文字を拒否し、NFKC正規化・小文字化・空白整理を行います。複数語と複数タグはANDです。部分一致の重みはコマンド・IDが10、タイトルが9、別名・症状などが8、タグが5、概要が2で、完全一致には加点します。同点は収録順を維持します。LLMによる意味解釈や回答の生成は現在の検索に含めません。

テーマ検索には、タイトル・概要・学習目標・確認ポイント・項目の見出し・説明・注意を抽出した `src/data/reference_search_index.json` を使います。コード例・利用条件・出典の全文は抽出しません。検索のためにテーマ画面の全データや外部資料を取得しません。入力コード、利用者の診断結果、学習の進捗も検索対象にしません。

テーマや関連トピックのタグを変更した場合は、次を実行し、生成された差分を確認します。

```sh
npm run update:search-index
npm run lint
npm run test
npm run build
npm run test:e2e
```

生成元の公開JSONを検証してから索引を作ります。起動・ビルド時には生成元と派生データの完全一致を確認し、古い内容や余分な項目を拒否します。検索結果のUI・索引・専用CSSは検索条件を指定したときだけ遅延読み込みします。

## 将来のLLMの役割

`AiSearchProvider.selectTargets` と `UniversitySearchProvider` は、ローカル検索で見つけた候補を選び直し、「探す・試す・直す・学習」へ案内する準備です。現在の画面には接続していません。検索語やLaTeXソースを送る引数はなく、テスト内の注入したfetchだけで契約を検証しています。

この方式は候補の選択・順序付けを担当します。未知の自然文を意味解析して候補を新しく発見する検索ではありません。大学側にも同じ公開IDに対応したカタログを用意する必要があります。将来、自由な検索語を送る設計へ変える場合は、情報利用の方針・利用者への説明・大学の承認を含めて別に設計します。

## Gateway契約案

`GET /v1/capabilities` には既存の解説機能と別の機能宣言を用意します。

```json
{
  "service": "latex-navigator-ai",
  "version": "1",
  "ai": { "explanations": false, "searchNavigation": true }
}
```

検索機能は `searchNavigation === true` のときだけ利用候補にします。省略・falseなら検索要求を送りません。不正な型は `unknown` です。どちらかの機能が利用できれば全体の接続状態は `available` ですが、解説ボタンは `explanations === true` を別に要求します。単にGatewayへ到達できたことを、本人認証や大学ネットワークの証明として扱いません。

検索要求の提案先は固定の `POST /v1/search-navigation` です。

```json
{
  "version": "1",
  "intent": "try",
  "candidates": [
    { "kind": "topic", "id": "math-fraction" },
    { "kind": "recipe", "id": "fraction" },
    { "kind": "reference", "id": "math" }
  ]
}
```

`intent` は `all / understand / try / fix / learn` の固定値です。候補は1〜20件で、種類とIDが登録済み・重複なしであることを検証します。要求全体の未知の項目も拒否します。`createSearchNavigationRequest` はローカル検索結果から種類とIDだけを取り出します。

応答は次の形のJSONだけを受け取ります。

```json
{
  "version": "1",
  "targets": [
    { "kind": "recipe", "id": "fraction" },
    { "kind": "reference", "id": "math" }
  ]
}
```

1〜6件で、要求に含まれた候補の部分集合だけを許可します。重複・未知のID・未知の項目・任意URL・自由な文章を拒否します。遷移先はアプリが種類とIDから組み立てます。AIの指定したURLやHTMLを表示・実行する処理はありません。

未設定・検索機能の非対応・認証要求・通信失敗・不正応答では、ローカル候補の先頭6件へ戻ります。不正な要求や候補ゼロでは呼び出しません。本文を含めて3秒、展開後32KiB、JSONのみ、Cookie送信なし、参照元送信なし、リダイレクト禁止、HTTPキャッシュなしの既存Gateway制限を使います。

## 接続前に確定すること

大学による利用許可、HTTPS Gatewayの管理、認証・認可、許可OriginのCORS、契約・IDカタログの一致、レート制限、ログ用途・保存期間、実環境での到達性を確認します。候補IDから利用者の関心分野が分かり得るため、IDのみの要求でも運用上の確認は必要です。認証情報をViteの公開環境変数へ埋め込みません。

実APIへの接続試験、検索補助の実画面への接続、大学側のLLM・Gateway実装は未実施です。既定の `VITE_ENABLE_LIVE_AI=false` と本番CSPの通信制限を維持しています。
