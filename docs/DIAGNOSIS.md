# 簡易診断と修正の確認

更新日：2026-10-12。「直す」と「まとめて調べる」で同じ字句状態に基づく診断を使います。TeXエンジンは実行せず、マクロの展開・外部ファイルの読み込み・依存パッケージの導入状況の検証は行いません。

## 対応するチェック

| 規則 | 表示と注意 |
| --- | --- |
| 波括弧の過不足 | 対応しない括弧の位置。未完の断片は注意とし、入力末尾への追加を断定しない |
| 環境名と閉じる順序 | 開始と終了の位置を比較。外側を先に閉じた場合は内側の終了を確認し、外側の終了名を無条件に置き換えない |
| 数式外の下付き・上付き | 利用位置を確認。本文のアンダースコアと数式の添字を区別 |
| 数式区切りの不整合 | 開始位置と対応する終了の種類。式全体の環境と区切りの重なりも注意として表示 |
| 数式内の段落区切り | 空行と明示的な `\par` を検出。コメントのみの行・通常の改行を空行と混同しない |

従来の5規則に `MATH_PARAGRAPH_BREAK` を追加しました。`alignat`・`flalign` とスター付きの形式も数式モードとして認識し、`gathered` は数式内部用として扱います。パッケージが実際に読み込まれたか、行・列の指定が正しいかまでは検証しません。

コメント、エスケープ、verb、主なリテラル環境を読み飛ばします。独自マクロ定義・外部入力・動的構文がある場合、その先の診断を省略しヒントを示します。xparse系のコマンド定義・DeclareRobustCommand・letなども省略対象です。すべてのTeX構文を認識する走査器ではありません。対応できない領域を正しいと認定しません。

## 行の確認と修正例

指摘の周辺コードと、分かる場合は対応する開始位置を示し、ボタンで編集欄に移動します。UTF-16の列位置を使い、WindowsのCRLF入力では編集欄が改行をLFへ正規化することも考慮します。入力の内容は書き換えません。入力変更後は結果を古いものと明示し、再診断するまで行移動を無効にします。

「修正例と確認手順」を開くと、説明・間違いの例・コピーできる修正例・必要パッケージ・出典を表示します。例はアプリ独自の短い固定例で、利用者のファイル全体を修正したものではありません。内容は開いたときに表示し、初期の結果を長くしません。指摘は「直す」で先頭3件、専用セクションで先頭5件を表示し、残りを展開します。上限は100件です。

## ログの確認手順

専用セクションでは、次の代表的なメッセージに固定の確認手順を付けます。

| メッセージ・報告 | 確認する内容 |
| --- | --- |
| Missing $ inserted / Bad math environment delimiter | 数式区切り・本文の添字記号・数式内の空行 |
| Undefined control sequence | 展開途中も含むコマンドの綴り・提供パッケージ・独自定義 |
| Environment … undefined | 環境名と提供元。任意の環境をamsmathで解決できるとは扱わない |
| File … not found | 綴り・パス・必要ファイル・導入状況。大学PCは授業・管理者の指示に従う |
| Reference … undefined | label/refのキーと位置、補助情報の再コンパイル |
| Citation … undefined | 文献キー、テンプレート指定の文献処理手順 |
| Extra } / Argument … extra } / Paragraph ended … | 報告行の前後の引数・波括弧・オプション引数 |

ログの一文から原因や修正位置を確定しません。未知のメッセージには手順未収録と表示します。メッセージに対応する既存トピックも案内するため、ログだけでも資料を探せます。ログ位置からソースへ移る条件や入力上限は [専用セクションの仕様](./WORKSPACE.md) を参照してください。

## 出典と検証の限界

数式モードと空行は [AMS / LaTeX Projectのamsmathガイド、第3節](https://www.latex-project.org/help/documentation/amsldoc.pdf)、ログと原因位置の違いは [Learn LaTeXのエラー解説](https://www.learnlatex.org/ja/lesson-15) に照合しています。文書構造・数式・相互参照・文献処理もLearn LaTeXの該当レッスンを参照し、該当する6資料の確認日と必要な参照範囲を更新しました。本文の全文や画像は取り込んでいません。診断の重大度や断片の扱いはアプリ独自の方針です。

単体・UI・PC/モバイルのブラウザで、正常・異常、コメント、リテラル、位置、コピー、変更前の結果、入力保護を検証します。教員による校閲、実TeXコンパイル、大学PCのエンジン・文書クラス、実際の学生による利用は未検証です。Linux/EmacsとWindows/TeX Liveのどちらでも、授業指定の条件が確定するまではエンジンの変更やコマンド実行を自動で勧めません。入力の保存・外部送信・学内LLMへの接続はありません。
