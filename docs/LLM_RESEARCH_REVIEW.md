# 学内LLM調査報告の整理

確認日：2026-10-12。利用者から提供された調査報告の評価です。報告者による「実測」を、このリポジトリで実施した試験として扱いません。APIキー・モデル名・実際のAPI接続先・アクセス統計の原文は収録しません。

## 確認範囲

[岡山大学研究・イノベーション共創機構の公式サイト](https://www.orsd.okayama-u.ac.jp/)の公開検索結果に、「ローカルAIサービス（おいとま）」の学内限定案内があることを確認しました。報告に挙がった総合マニュアルは今回の閲覧ツールで取得できず、学内限定案内ページは401でした。

モデル一覧取得、推論、CORSのpreflight、キー発行、認証、ダッシュボードの取得は行っていません。報告内のAPI形式・モデルID・上限・CORS・エラー形式・保存方針は一次資料未照合です。

## 設計へ反映できる候補と残る確認

| 報告内容 | 扱い・追加確認 |
| --- | --- |
| OpenAI互換のモデルAPIがある | HTTP形式の接続アダプターを検討する材料。正確な仕様と要求・応答例を確認してから実装する。現行の独自Gateway契約とは別 |
| 学内ネットワークでキーを発行できる | 利用者から共有済みの前提。学生向けサービス利用・サービス側保管・キー共有の許可を意味しない |
| CORSで任意Originを許可するとの実測 | 報告として受領。技術的にブラウザから読めることと、公開アプリでの利用許可・学外アクセス条件を分けて確認する |
| APIキーをlocalStorageへ保存する案 | 現行の非保存方針では採用しない。大学管理Gatewayでの保管を優先して検討する。利用者個別キーをメモリだけで扱う方式も、直接接続を正式に許可された場合に別途評価する |
| 学生が利用対象との記述 | 報告内には学生対象の明示がないとの記述もある。アカウントでログインできることからサービス利用権限を推定しない |
| コンテキスト200kと32768の記述 | 不一致を未解決として扱い、モデルごとの実効入力・出力上限を担当者に確認する。大きい値を採用しない |
| 入力を再学習に使わず本文を保存しないとの記述 | API経由にも適用されるか、アクセスログ・一時保存・会話・バックアップを含む範囲、保存期間・閲覧者・削除を確認する |
| OpenCodeが不要との判断 | 説明・コード例の回答だけなら、互換モデルAPIを使う構成を検討できる。ファイル操作・シェル・エージェント実行を追加する必要はない |

## 優先する確認

1. 学生向け公開WebアプリでのAPI利用と、大学管理Gatewayの設置・キー保管の可否。
2. 質問・TeX断片・ログの送信条件、APIの保存/学習利用、アクセスログの保存期間・閲覧者。
3. 学外・VPNからの利用可否と、ブラウザ向け利用の正式な条件。
4. モデルごとの実効トークン上限、レート制限、待ち時間、出力形式・ストリーミング。

大学固有の運用許可は担当者の回答で確認します。LLM回答だけで承認済みに変更しません。資料を共有する場合はキー、認証ヘッダー、Cookie、個人情報、アクセス統計を除いてください。

## 現在の実装

配布版はAI無効を維持しています。キー入力欄・localStorage保存・ブラウザからのモデルAPIへの直接接続はありません。配布版の入力を送信する契約は変更していません。

利用者の追加依頼により、開発中の通常画面に実APIの通信処理を実装しました。設定したキーを端末のサーバー側で扱い、質問と添付・貼り付けたTeX・ログを「送信」で渡します。入口と送信直前にAPIの利用可否を自動確認します。配布ビルドには含めません。2026-10-12、自作の短い質問で実APIの回答とLaTeXコードを取得しました。Wi-Fi限定のアクセス制限仕様・ログ保存期間は未確認です。[接続手順](./LLM_CONNECTION.md)に手順と制限を記録しました。

現行のGatewayは独自の `/v1/capabilities`・`/v1/explanations`・`/v1/search-navigation` を想定しています。モデルAPIのURLを公開設定へ入れるだけでは、この契約や認証に対応できません。大学側条件を確定してから、GatewayとモデルAPI間の変換、学生の認証、送信前確認、回答検証を設計します。

必要情報の一覧：[LLM_INTEGRATION_CHECKLIST.md](./LLM_INTEGRATION_CHECKLIST.md)。
