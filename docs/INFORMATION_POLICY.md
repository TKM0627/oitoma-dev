# 情報利用と確認状況

公開構文情報のみを収録する静的アプリです。資料の確認とソフトウェアの動作検証を区別し、大学の承認や学習効果があるような表示を避けます。

## 出典と利用範囲

- `src/data/references.json` に資料の公開URL、発行元、確認日 `checkedAt`、参照範囲 `scope`、資料種別 `sourceType`、利用方法 `usage` を登録します。共通資料は37件です。環境・追加ログ案内用の6件は `src/data/support_references.json` に登録し、対象画面で読み込みます（計43件）。
- KaTeX・GNU Emacs・Overleafの製品設定の開発元文書、jlreq・amsmath・TeX Liveの保守者文書、Learn LaTeXの制作元チュートリアル、Overleafの構文解説を参照しています。種類を分けて画面に表示し、第三者の解説をLaTeX本体の公式仕様と同一視しません。既存資料を検索・照合した日は2026-10-10、新規の記号一覧の資料は2026-10-11です。診断強化で使う6資料は2026-10-12に再照合しました。資料がその後も同じ内容であることを保証する日付ではありません。
- 短い構文例と日本語の説明を作成し、資料へのリンクを提示します。資料の全文、画像、配布テンプレート全体は取り込みません。各資料に書かれた構文の条件と、このアプリ独自の診断・学習方針を区別します。
- トピック・クイズ・日本語設定・静的解説・テーマ別資料の各項目には明示的な出典IDを付けます。静的解説の出典を、関連トピックから推測して補う処理は使いません。コードの測定値・書誌情報などが架空の場合は、その旨を表示します。
- 参考URLはHTTPS、管理対象の正確なホストとパスに限定します。認証情報・クエリ・独自ポート、似たホスト名、管理外の資料は拒否します。許可リストは資料の内容の正しさや安全性を証明するものではありません。
- 外部リンクは利用者の選択で開き、`noopener noreferrer` と `referrerPolicy="no-referrer"` を指定します。リンク先の情報の扱いは各サイトの方針によります。

## 確認したこと・未実施のこと

| 確認の種類 | 現状 | 意味・限界 |
| --- | --- | --- |
| 登録した公開資料との照合 | 開発時に実施 | AIを利用して作成した説明と資料を照合。資料にない断片診断の重大度や学習順はアプリの方針 |
| 教員などによる人手校閲 | 未実施 | 大学・教員の監修、承認を表示しない |
| アプリの動作検証 | 単体・UI・ブラウザで実施 | 検索、生成、簡易診断、出典の整合性、入力の非保存・非送信などを検証 |
| 実際のTeXコンパイル | 未実施 | KaTeX表示や固定出力のテストから、TeX文書全体の成功を推論しない |
| 学習効果・大学での採用 | 未測定・未実施 | 自己チェックやクイズを習熟度や成績の証明として扱わない |

`reviewed_explanations.json` の `reviewed` は、資料との照合を終えた説明を表示するための管理フラグです。`verificationMethod: "primary-source-comparison"`、`humanReview: "not-performed"` を別に保持し、画面にも人手校閲未実施を表示します。CODEX_PROMPT.mdが想定する人手検証は、この開発作業だけでは完了できていません。授業で正式な教材として用いる前には、教員による内容の校閲が必要です。

上記の `primary-source-comparison` は既存の管理値です。すべての参照先がLaTeXの開発元文書であることを意味せず、実際の資料種別は出典ごとの `sourceType` で示します。テーマ別資料は `verificationMethod: "source-comparison"`、`status: "prototype"`、`humanReview: "not-performed"`、`texCompilation: "not-performed"` を保持します。参照範囲と編集方針は [テーマ別資料の試作](./REFERENCE_CONTENT.md) に記録しています。

## 入力情報の流れ

| 情報 | 扱い |
| --- | --- |
| 貼り付け・編集したLaTeXコード | Reactのメモリ内。外部・LLMへの送信、URL・history state・Storageへの保存は行わない。診断画面を離れると消える |
| レシピから診断への引き継ぎ | 固定レシピIDと検証済み選択値をhistory stateに渡し、固定コードを再生成 |
| 検索語 | Reactメモリのみ。入力・戻る・種類変更でもURL・history state・Storage・APIへ渡さない。クリア・再読み込み・文書離脱で破棄 |
| 登録済みタグ・結果の種類・全項目表示・コースID | 固定値のみURLハッシュに反映。検索から移動した場合のhistory stateにも検索語を含めない。未知の項目は引き継がない |
| 専用セクションの質問・ファイル名・TeX・ログ・結果 | メモリ内のみ。URL・history state・Storage・外部API・学内LLMへ保存・送信しない。入力ファイルを教材・検索索引へ自動追加しない |
| 記号一覧内の絞り込み | メモリ内のみ。URL・履歴・Storageへの保存や外部への送信は行わない |
| 利用環境・学習チェック・クイズ回答 | メモリ内。再読み込みで消える。URL・履歴・Storage・外部へ保存・送信しない |
| 読み込み・外部資料 | 配信元から静的ファイルを取得。資料へのリンクを選択した場合は移動先と通信 |
| 将来の学内AI | 現在は未設定・未接続。解説は登録済みID、横断検索は候補の種類・IDと固定の目的・契約版だけを扱う契約案。検索語・入力コード・任意プロンプトを送る引数はない |

利用者の行動を記録する解析SDKはありません。配信元や移動先が保持する通信ログを、このアプリから管理することはできません。

「まとめて調べる」は既存の公開説明と固定例を使い、入力ソース・ログを根拠資料として共有しません。参照資料は37件です。診断強化で使う6件を再照合し、確認日と必要な参照範囲を更新しました。ログの報告・簡易チェック・断定できないタイポ候補を分けて表示します。[対応範囲](./WORKSPACE.md)を参照してください。

## 更新時の検証

同梱JSONはビルド・開発サーバー起動時とテストで検証し、未知の項目、欠落した出典情報、重複ID、存在しない参照、不正URL、コードの不正な制御文字を拒否します。不正なデータを含む本番成果物は生成しません。非公開情報を含み得る未知の項目を黙って削除して採用しません。ただし、スキーマで個人情報の意味を完全に判別できるわけではないため、収録する文章自体の確認も必要です。

テーマ別資料もビルド・開発サーバー起動時に検証します。各項目に出典を要求し、既存のトピック・レシピ・エラー事例への参照を解決します。未実施の校閲やTeXコンパイルを実施済みとして書き換えたデータは、現在の試作スキーマでは拒否します。

テーマ検索の派生JSONは、検証済み公開データから抽出した内容とビルド時に完全一致を確認します。追加の任意フィールドや未更新の検索用データを採用しません。将来の検索連携は [契約案](./SEARCH_AND_AI.md) に記録しています。候補IDから利用者の関心分野が分かり得るため、大学側のログ用途・保存期間も仕様確定時に確認します。

資料を更新する際は、実際に参照範囲を読み、説明・コード・出典IDを照合してから確認日を変更してください。照合していない解説は `reviewed: false` にします。URLだけを開いたことや自動テスト成功を、内容の校閲として扱わないでください。ライセンス通知は [THIRD_PARTY_NOTICES.txt](../public/THIRD_PARTY_NOTICES.txt) にインストール済みの実行時依存パッケージから収録しています。依存更新時にはバージョンと通知を更新してください。

学生向けの言い換えは `src/data/purpose_phrases.json` の固定データです。26トピック・70表現は開発時に作成した候補であり、学生の質問履歴や提出物から収集したものではありません。ビルド時に既存トピックへの参照・重複・制御文字・長さ・未知の項目を検証します。追加資料も既存の公開URLポリシーと同じスキーマで検証し、外部リンクの保護を維持します。

Emacsのモード選択も画面のメモリだけで扱います。ターミナルコマンドには検証済みエンジンと固定ファイル名だけを使い、質問・ソース・実際に読み込んだファイル名をシェル文字列へ混ぜません。アプリによるコマンド実行や実機・教員による検証は追加していません。
